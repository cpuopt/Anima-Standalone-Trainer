# Vue 前端迁移与协作方案

状态：已于 2026-10-16 19:00（北京时间）开始实施。代码迁移与验收记录见 [Vue 前端指南](VUE_FRONTEND.md)。下文保留原阶段规划。

基线：`0955de8`；目标：Vue **3.5.44** + TypeScript + Vite + shadcn-vue + Pinia。

## 1. 目标与范围

把当前原生 HTML/JavaScript 前端迁移为组件化前端，保持现有任务、训练、采样及配置文件兼容。迁移后可以按功能扩展文件管理等页面。

本次覆盖现有九个标签页：Training、Dataset、Network、Multi-GPUs、Prompts、Samples、Console、TensorBoard、Settings，以及任务管理、硬件监控、主题和背景。

保留 Express/WS 后端、Python 训练流程、现有 API 和 TOML 文件格式。兼容已有 Anima 与 Krea 2 任务，保留注册表中其他架构的现有展示和读取行为；不扩大新建任务的架构范围。

文件管理、训练算法改动、权限系统和大幅交互重设计另立任务，不计入本次迁移。

## 2. 技术与发布方式

- 新前端位于 `training-ui/frontend/`，有独立 package.json、锁文件和 TypeScript 配置；Vue 固定为 3.5.44。
- shadcn-vue 组件提交到仓库，统一主题变量；Tailwind 按所选 shadcn-vue 稳定版的兼容要求安装并锁定。
- Express 继续使用 CommonJS；新前端使用 ESM，不修改整个 training-ui 的模块类型。
- 迁移期间旧界面保留在 `/`，新界面使用 `/ui/`，在不同页面运行；不让 Vue 和旧 app.js 同时管理同一 DOM。
- Vite 开发代理转发 `/api`、根路径 WebSocket、`/tensorboard` 和 `/uploads`。WS 的根路径升级协议保持不变。
- 生产构建输出 `frontend/dist/`，Express 仅在 `/ui/` 下提供该目录及对应页面回退，不吞掉 API、旧界面和 TensorBoard 路由。用户仍通过原服务器端口访问。
- 发布时启动脚本负责检测构建缺失或过期；支持明确的依赖安装和构建命令，避免每次启动无条件下载依赖。构建失败必须有可读错误。
- 所有任务验收后再切换默认入口；旧入口在过渡发布保留，后续单独决定删除时间。

建议目录：

```text
training-ui/frontend/
  src/
    app/                  # 入口、布局、导航、主题
    components/ui/        # shadcn-vue 基础组件
    components/forms/     # 通用字段、错误、帮助文本
    services/             # API client、WebSocket、请求取消
    stores/               # jobs、editor、runtime、settings
    domain/               # 类型、配置映射、校验、纯计算
    features/
      jobs/
      training/
      dataset/
      network/
      multi-gpu/
      prompts/
      samples/
      console/
      tensorboard/
      settings/
  tests/
```

## 3. 先固定公共契约

页面并行开发前，由主代理提交以下公共契约与代表性配置样本：

1. API 请求与返回类型、错误处理、任务名与样例路径编码规则。
2. JobDocument：完整原始 config/dataset，加上已解析的架构和提示词；页面只修改自己拥有的字段。
3. Draft 与 SavedSnapshot：未保存判断、保存成功后更新快照、保存失败保留草稿。多个保存接口不能假设原子成功，失败时分别记录。
4. 配置读写：现有 PUT 接口对 config/dataset 分别整体覆盖，必须基于完整原对象合并所编辑字段；未编辑 dataset 时不提交它。保留未展示字段，区分缺省、空字符串、false、0；不以表单默认值无条件覆盖原配置。
5. 架构能力表：字段可见性、可编辑性、默认值、网络模块、训练/采样限制，避免模板内重复散落判断。
6. runtime：按任务分离训练状态、日志、采样和 TensorBoard 状态；界面禁止操作与后端限制一致。
7. WS：单一连接入口、重新订阅、断线恢复、卸载清理；切换任务时拒绝旧请求结果和旧任务消息。`hw_stats` 等全局事件单独处理。
8. 轮询与异步副作用：按任务/页面生命周期取消，提供超时、错误和重试状态。
9. 本地持久化：明确兼容读取旧 `lastJob`、`prompt_transient_${job}`、`sample_order_${job}` 等键；本地采样草稿、样图顺序与服务端配置分别管理。

现有 `krea2.js`、`layer-rank.js`、`adapter-matrix.js`、`lbai.js` 的纯逻辑优先复用。通过受控封装逐步迁移；不由多个页面各复制一份规则。后端现有引用在迁移时继续有效。

## 5. 协作规则

最多同时四个代理：主代理负责公共层、集成、检查与合并；三个功能代理各自负责独立功能目录。

- 同一时间一个文件只有一个负责人；主代理维护 package/锁文件、server.js、启动脚本、services、stores 和公共配置映射。
- 功能代理可以提交所需契约变更建议，由主代理修改公共层；不各自创建请求客户端、WS 连接或另一套全局状态。
- 三个功能代理在 T02 稳定后并行：A 做 T03→T07，B 做 T04→T08，C 做 T05→T09。
- T06 与 T10 为集成关卡。跨域规则由主代理集中整理，功能代理按约定接入。
- 优先使用独立工作树与功能分支；分支从同一个契约基线创建。每个里程碑整合后同步基线，再开始下一批。
- 任务交接必须给出：修改范围、契约变更、已验证场景、未验证场景、剩余问题。没有实际运行的检查不得标成通过。
- 每个子任务形成可独立审阅的提交；修复必要问题后再进入集成基线。提交、推送按用户当次授权执行。
- 独立评审安排在关键里程碑，以读取和复核为主，不在评审过程中同时改动负责人文件。

## 6. 里程碑与执行批次

### M0：可测消耗的小批次

执行 T00、T01，以及 T02 的最小部分：任务列表→切换任务→显示架构→读取配置→修改少量 Training 字段→保存并重新读取。

此阶段只开放已完成的字段；使用完整原始配置合并受控字段，避免把尚未迁移的字段清空。保留旧界面用于完整操作。

验收：两种架构各用独立测试任务，保存后其他字段不变；连续快速切换任务不会串配置；构建后 /ui/ 可访问、旧入口可用。

记录同一模型、同一推理与速度设置下的额度前后值、重置时间、实际修改和返工范围。跨窗口重置或其他会话同时使用时，该样本不用于直接外推。根据实测再调整后续批次；不设没有依据的百分比承诺。

### M1：完整配置编辑

完成 T02–T06。任务管理、Training、Dataset、Network、Multi-GPUs 具备完整配置读写。所有互斥规则和矩阵计算与现有行为核对。

验收后形成第一份可用于真实训练前配置检查的版本。

### M2：训练、采样与监控

完成 T07–T09，整合启动/停止、WS 日志、硬件状态、训练中样例和独立采样。补齐画廊和设置。

存在真实权重与合适运行环境时验证真实训练/采样；环境不具备时，接口模拟验证与真实模型验证分别报告，不将模拟成功算作真实运行通过。

### M3：发布与默认入口切换

完成 T10。确保生产不依赖 Vite 开发服务器，Windows/Linux 启动路径明确，已有任务无需转换。完成所有阻断项后切换默认入口，保留可用的旧入口回退。

## 8. 完成定义

- 清单内现有功能均有对应入口和验收记录，未解决项明确列出，不以“页面已渲染”代替功能完成。
- 已有任务无需手工修改配置；序列化和架构能力规则只有一个维护入口。
- 关键流程、现有测试、类型检查、构建通过；真实模型和跨平台检查如受环境限制，单独标明。
- 用户通过现有启动方式访问生产界面，不需要常驻第二个前端进程。
- 文档包含安装/开发/构建/回退命令，并交付变更摘要与实际验证范围。
