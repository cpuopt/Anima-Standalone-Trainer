# 训练显存诊断与逐次文本缓存

控制台硬件监控增加了训练进程的模型 / 内容表。新启动的本仓库 NetworkTrainer 训练进程默认上报轻量状态，通常最多每秒在训练节点更新一次；模型加载、迁移、采样和保存等边界会立即更新。未集成此接口的 vendor 后端、独立生成进程与已在运行的旧进程不会自动提供内容明细。服务器和训练进程都需要加载新代码；更新不会注入或重启已有训练。

## 读懂监控

- **模型 / 内容**：DiT、文本编码器、VAE、LoRA 等训练网络、梯度、优化器状态。CPU 行表示张量存储位于系统内存，CUDA 行表示 CUDA 分配。跨模型共享的存储只归属一次，防止重复计算。
- **活跃张量 allocated**：PyTorch 仍然使用的 CUDA 分配。**预留 reserved** 包括活跃分配与分配器缓存；`reserved - allocated` 显示为“未使用预留”，并不代表全部能立即释放。部分分裂块仍与活跃张量共用段，CUDA 图私有池也有生命周期限制。
- **分裂块内未用空间**：`inactive_split_bytes.all.current`，帮助识别原生分配器的分裂块情况，不是全部不可释放空间的总和；部分分配器后端可能不提供该统计。原始快照另外记录 allocator active bytes 和 allocation retry 次数。
- **区间峰值**：开启节点诊断时，自上一个采样节点以来的 CUDA 分配峰值；仅监控模式不重置峰值，显示进程迄今的峰值。
- **未归属活跃分配**：allocated 扣除当前设备已归属存储后的差值，可能包含激活、临时张量、工作区等，不能据此直接判定泄漏。
- 新快照显式记录 `cuda:N`；旧快照的 `cuda` 在内容表仅含一张 CUDA 卡时解析为该卡，防止把全部 allocated 错算成未归属分配。旧快照同时含多张卡且设备不明确时，不显示不可靠的差值。模型存储清单与 allocated 采样时间可能相差数秒，因此差值仍为估算。
- **Windows 专用 / 共享 GPU 内存**：PDH 提供的该 PID 在所有适配器上的统计，不能与某张卡的 PyTorch 分配作严格等式比较。PDH 不可用时显示未知，而非 0。
- 模型参数的 CUDA 分配不代表全部物理驻留在显卡 DRAM。驱动不暴露“哪个模型的哪些页进入共享内存”，因此内容表是存储分配归属，无法逐模型精确拆分物理专用 / 共享驻留。
- 内容表是最近节点快照。慢前向或编译过程中可能暂不更新；超过 15 秒显示“等待更新”。结束进程、上次启动及无效快照不作为当前数据展示。

## 记录关键节点

在**控制台页 → 硬件监控 → 显存分配详细记录**中选择是否开启，默认关闭。该选项保存为当前任务的 `training_arguments.memory_trace`，沿用界面的配置保存机制，下次启动训练时生效。任务运行、配置加载或保存期间开关禁用；服务端同时拒绝运行中修改详细记录开关、同步开关和采样间隔，防止通过其他页面或旧请求绕过。已有任务显式保存的选择会保留。

训练配置 `[training_arguments]`：

```toml
memory_monitor = true
memory_trace = false
memory_trace_every_n_steps = 50
memory_trace_sync = false
```

`memory_monitor` 默认开启；`memory_trace` 默认关闭。开启 `memory_trace` 时，诊断只写入任务 `logs/memory_trace_*_pid*.jsonl`，按 PID / rank 分文件，不输出到训练控制台。诊断自身的错误另存到 `logs/memory_errors_pid*.jsonl`，相同节点的重复错误至少间隔 60 秒。旧配置的 `memory_trace_console_interval` 仅保留解析兼容，不再控制台输出。UI 只读取很小的原子状态快照，不重复读取持续增长的 JSONL。常规训练的分配器计数最多每秒更新，模型存储清单最多每 5 秒刷新，模型迁移等阶段边界立即刷新。

`memory_trace_sync` 在选中的诊断节点等待 CUDA 完成，有利于划分操作区间，但会影响吞吐；普通监控更新不强制同步。Windows 驱动计数器仍存在刷新延迟，不能把单个节点的共享内存增量解释为精确到某条 CUDA 指令的因果关系。详细逐节点排查可临时设 `memory_trace=true`、`memory_trace_every_n_steps=1`，必要时再开启同步，排查结束后关闭。详细日志默认每 50 个 microbatch 采样一次，前三批始终写入 JSONL；缓存阶段单独计数缓存批次，避免训练步数尚为 0 时每批都触发“前三步”记录。

记录范围包括模型加载、VAE latent 缓存及卸载、文本缓存或编码器放置、accelerator.prepare、恢复状态、每批 latent 准备 / 文本编码 / DiT 前向 / loss、反向、梯度同步及裁剪、优化器更新及清梯度、验证、采样提示词 / DiT 全块搬入 / 去噪 / VAE 上传与解码 / 卸载，以及模型权重和训练状态保存。

每条记录含时间、PID、rank、节点、optimizer step、microbatch、latent / image / token 形状、allocated / reserved / 空闲缓存 / 区间峰值，以及可用的 Windows 专用 / 共享内存与相邻节点增量。模型表在迁移节点及监控更新时刷新。对比相同形状下多次 `loss_released` / `sample.after_restore` 的 allocated 基线，区分一次性优化器初始化、分辨率变化、编译图保留与持续增长；reserved 增长并不等于有活跃张量泄漏。日志采样不调用 empty_cache 来伪装释放。

## 此次生命周期检查

| 环节 | 发现 | 处理 |
| --- | --- | --- |
| 在线文本编码 | 未缓存时 Qwen3 每批运行并驻留 CUDA | 属于所需分配；新增逐次文本缓存以支持打乱标签后卸载 Qwen3 |
| 长期采样提示词缓存 | 原本把编码结果保存在 GPU 字典 | 保存 detached CPU 张量，采样时按需搬入 |
| 采样去噪 | 原本提前把 VAE 搬入 GPU，与 DiT 共占显存 | VAE 在解码阶段才上传，每张图解码后恢复原设备，异常时也清理其内部缓存 |
| VAE 解码前 | 正负提示词和交叉注意力条件仍被局部变量持有 | 解码前解除这些引用，再清理缓存 |
| 非缓存分块图像编码 | cat 后原分块 latent 列表与末块引用继续存活 | 合并后立即删除已用完的分块引用 |
| 每批训练 / 验证后 | loss Python 引用会存活到采样、保存及下一次前向 RHS | 日志只保留标量，及时删除 loss；反向后的大部分保存张量原本已由 autograd 释放，不把此项夸大为主要泄漏 |
| LoRA 保存 | `detach().clone().to('cpu')` 先产生 GPU 临时副本 | 直接创建独立 CPU 副本，维持保存 dtype 与 DoRA scale 精度约定 |
| 优化器状态 | Adam 类状态在首次更新 / resume 后常驻 | 属于续训需要的分配，列入明细并记录前后峰值，不每步清空 |
| block swap 采样 | 原有逻辑会尝试将 DiT 全部块搬回 GPU | 加入独立前后节点，保留原有 OOM 回退与恢复行为；驱动回退到系统内存时可能不抛 OOM，仍需观察该区间 |
| 编译与多尺寸 bucket | torch.compile 可能产生图缓存 / 重新编译开销 | 保留用户配置，记录 bucket 形状及节点峰值；现有证据尚未证明是主因 |

此前实测显卡专用显存几乎用满，训练 PID 同时占用约 1.6 GiB 共享 GPU 内存，支持“显存压力导致回退”的判断；旧进程没有这些内部节点记录，不能倒推出其首次换页发生在哪一步。上述修改尚不能保证当前分辨率 / batch 在所有 bucket 都不进入共享内存，需要新训练进程的实测确认。

## 按实际使用次数缓存打乱后的文本

Anima 的训练配置新增：

```toml
cache_text_encoder_variants = true
cache_text_encoder_outputs_to_disk = true
```

该选项自动启用文本磁盘缓存，只用于冻结文本编码器的训练。预处理为每个**图片 × 轮次 × 重复索引**创建一个确定性编码，训练时按 bucket 中该图片的重复位置读取，避免随机取固定小池导致反复复用同一版本。标签本身较少时，多个独立随机结果仍可能相同，这是正常的随机排列结果。

- 使用原有 `process_caption` 处理 keep_tokens、Tags 打乱、自然语言保留、前后缀、wildcard、Tag Dropout 和 Caption Dropout。逐次模式在预处理阶段固定这些随机选择，训练时不再次随机丢弃同一编码。原有固定缓存 / 在线编码模式保留原行为。
- 尊重 `epoch_sample_rate`，只为该轮选中的图片及重复次数准备编码。persistent worker 通过原有共享 epoch 同步选择正确版本；同一逻辑批次被分布式 sampler 为补齐而重复派发时，读取该逻辑批次对应版本。
- 多进程按缓存条目分工，所有 rank 完成后才发布索引。沿用磁盘缓存的共享文件系统前提。
- 缓存路径包含模型文件路径 / 大小 / 修改时间、tokenizer 词表及特殊 token、caption、文本增强设置、随机种子、token 长度及 caption / 编码策略代码等指纹。更改这些内容会生成新目录；旧目录保留。未做大型模型文件全量哈希，因此手工保持相同大小和修改时间替换权重不受该快捷指纹保护。
- 每个文件还校验变体身份和必要 tensor 键。写入采用临时文件后原子替换；损坏文件预处理时重建，训练中缺失时明确报错，不退回错误的固定 caption。
- 同样配置重启 / 续训复用缓存，轮次与重复位置选择不依赖 worker 随机状态。切换自旧在线编码训练时，无法还原旧模式此前随机产生的标签顺序。
- 预处理和磁盘占用按规划使用次数增长，不使用固定大小池。恢复训练时会检查整个规划轮次范围，已有有效文件跳过。step 模式按 dataloader 长度、world size 和梯度累积估算所需轮数。
- 当前明确不支持 `token_warmup_step > 0` 与分辨率日程；这些设置会改变与全局 step 绑定的文本处理或数据日程，不能静默使用不准确的预计算结果。

`white parabellum_v2` 保持逐次文本缓存开启，下一次启动配置已开启仅写文件的显存诊断（每 50 批采样）、关闭 CUDA 同步，保留硬件监控明细。配置和代码不会热替换已运行的 Python 进程；已在运行的任务需要重新启动才会应用。最初修改的原文件备份在 `.runtime/diagnostic-backups/20261103-memory-trace/`，限频修改前的文件在 `.runtime/diagnostic-backups/20261103-memory-throttle/`，仅写文件修改前的文件在 `.runtime/diagnostic-backups/20261103-memory-file-only/`；回滚时应在训练停止后只恢复对应文件。
