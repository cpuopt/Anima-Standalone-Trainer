# 控制台设计共同规格

用户要求：重新设计本项目“控制台”tab，利用现有左右布局左侧下方的大块空白。

根因来自源码：宽屏≥1550px时，硬件区至少600px，日志区至少600px且比例1:1.25；左侧内容高度由GPU数与显存节点决定，日志却是固定视口高度。单GPU或没有节点快照时，左侧会提前结束。

输出：三个可操作、离线HTML方向；画布1920×1080与1440×900，另验844×390和390×844；六候选缩略图。原型确认前不修改生产Vue页面。沿用Training Studio已有中文字体、蓝色语义和状态标识，重点改变空间分配。

共同信息：CPU/温度、RAM、GPU利用率/温度/显存/功耗、显存分配节点及过期标识、CPU卸载位置、日志、自动跟随/清空显示/复制。显存详细记录开关保留“运行时锁定，保存后下次启动生效”的语义。

数据边界：hardware.js推送当前硬件快照，memory-view.ts展开节点内模型存储；没有历史时序数据库。三版均不虚构“已有实时趋势”或训练损失图接口。原型数值、步骤和日志统一标为演示；内存条是当前快照的结构分解，不是历史趋势。

交互：日志搜索、级别筛选、自动跟随、换行、复制/导出、清空显示及恢复演示；资源面板可收起；演示状态切换单卡/双卡、有明细/无快照、训练/空闲/断线。无真实生成、保存或训练操作。

Form五问：用于训练/采样时近距离排障；视线在“现在做什么”和“GPU/内存在哪”之间移动；温度冷静、低视觉噪声；容量以日志行宽与节点明细为主；形式来自当前快照与连续事件这两种不同时间尺度。

方向A：资源变成横向仪表带，下面日志占全宽，底部显存明细可展开。
方向B：保留左右结构，硬件栏缩至320px左右，将模型位置和关键节点放在其下，日志获得剩余宽度。
方向C：日志充满工作区，资源压成底部状态带；需要排障时打开诊断抽屉。

适配：不依靠占位卡片填空；窄屏顺序重排，横屏日志保持可读；可滚动内容各自拥有滚动区域。日志正文14px，辅助标签≥12px。
