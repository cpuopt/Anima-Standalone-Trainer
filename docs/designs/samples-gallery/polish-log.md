# 原型看图打磨记录

使用 Node Playwright + 已安装 Edge 截图；Python版polish/design_lint/compare因缺少Python Playwright主动跳过。没有安装或下载依赖。以真实浏览器截图、断言和人工看图替代。

## 第一轮

截图：`screenshots/round-1/`。桌面1440×900，手机390×844/375×812，横屏844×390，平板768×1024；真横图和真竖图分别验证。

- A：默认两列/组过大，一屏图数不够；高密度后图底尺寸与轮次会挤；图库高度用固定减法不够稳。修改为108px目标列宽、隐藏重复的尺寸文本、主体flex占满剩余高度。
- B：等格图隐藏所有说明后缺乏轮次位置；底部区域在手机高度预算中不够清楚；参数覆盖图像容易打扰观看。修改为常驻短轮次标签、统一主体flex高度；详情默认收起参数，点击参数打开悬浮检查器。
- C：手机默认省略同一轮次第二张图，妨碍直接进入每张图；窄列重复图底标签太挤；滚动高度固定值有误差。修改为同格两图都显示、移动端去掉已由行列提供的重复标签、主体flex占满。

## 第二轮

截图：`screenshots/round-2/`。已人工查看三版桌面图库、A手机竖图详情、B手机横图详情及横屏详情、C手机图库和桌面横图详情。

- A：现在36张演示图均可在桌面首屏直接查看；图间距5px，右侧横图组较早结束是保留原比例分组的取舍。去掉尺寸叠加后标签更干净。图库不是等格，可通过尺寸滑杆增大图片。
- B：深灰背景让缩略图形状易辨；常驻短轮次标签解决定位；默认沉浸详情保留大画布，参数随时可开。竖屏横图保持完整构图，余下黑边属于画幅差异，不强行裁切。
- C：桌面行列轴清楚；手机所有图都能点，横图在窄格里较小，是矩阵模式的取舍；详情仍可独立放大。建议需要比较训练变化时选此结构。

三版重点交互均通过：图像wheel缩放、拖动平移、复位、1:1、参数区wheel不缩放图像、Esc关闭、搜索、多选、横竖屏适应、横竖图适应、无横向溢出、无控制台异常。

证据：`screenshots/round-2/verification.json`；第一轮/打磨后并排记录：`polish-before-after.jpg`。六候选缩略图为`thumbs-preview.png`。

初稿阶段未修改生产页面。三版共同的顶部项目Tab用于产品上下文，暂不跳转到训练配置等其他页面；刷新演示状态、演示参数都明确标注。

## 横屏空列问题复现及修正

用户反馈横屏仍未占满宽度。重新测量图片最右边缘，发现上一轮只验证了分组容器宽度，未验证实际图片覆盖范围。CSS多栏自动平衡留下空列：844px横屏右侧空116px，1920px空472px，2560px空1148px。

单Prompt改用auto-fit CSS Grid，空列收起，现有图片均分可用列宽；全部模式保留分组瀑布流。手机竖屏单Prompt仍固定3列密铺。

以844、1024、1440、1920、2560、390宽度分别验证三个Prompt，共18种组合；实际缩略图的最左/最右边缘均与图库边缘对齐，空隙为0px，无页面横向溢出。全部模式恢复36张/3组。截图和测量JSON在`screenshots/full-width-grid/`。已查看844横屏及1920宽屏截图。
